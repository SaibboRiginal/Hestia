- Only Hecate has a connection model: `Hestia-Hecate/app/connections.py` (`Connector`: `item/state/submit/action/forget`,
  `GET|POST|DELETE /api/gateway/connections…`) drawn by `<hecate-connections>` (`ui/src/connections.ts`) on the
  «Devices» page and in the guided setup. Connectors: `google`, `garmin`, `phone`.
- Outside it, only `.env`:
  - Apollo ComfyUI: `APOLLO_COMFYUI_URL` (an address, not a secret) + `APOLLO_COMFYUI_KEY`; nothing in Settings, setup, Ctrl+K.
  - Lares Home Assistant: `LARES_HA_URL` (address) + `LARES_HA_TOKEN`.
  - Hecate Outlook: `OUTLOOK_CLIENT_ID/TENANT_ID/CLIENT_SECRET/REFRESH_TOKEN`; the refresh token from the device-code

  - Hermes Web Push: `HERMES_VAPID_PUBLIC_KEY/PRIVATE_KEY` generated by hand with `npx web-push`.
- The Google OAuth client typed in the card goes to `Hecate/data/google_client.json`; env `GOOGLE_CLIENT_ID/SECRET` wins.
- The setup writes typed secrets into a module's `.env` (Hephaestus `setup/secrets.py`, whitelist + `ORACLE_KEY_*`,
  `ECHO_KEY_*`); Oracle and Echo re-read them live (`hestia_common.env_keys`, `LIVE` in `setup/service.py`).

## 2. Goal
Every external thing a module needs is linked from the WebUI the same way, like plugins: one page «Connections»
(«Collegamenti»), one card, a «Test» button, found with Ctrl+K and from Settings. `.env` keeps only secrets and
infrastructure, and the owner never opens it: a key typed in a card is written there by Hestia.

## 3. Scope and design

### 3.1 Contract (`hestia_common/connections.py`)
- `Connector` (moved from Hecate, same shape) + `group` (`account` · `device` · `home_service`), `keywords`
  (search words, English, e.g. `comfyui`, `images`) and `test()` (the «Test» button → `{ok, detail, facts[]}`).
- `Connections(module, prefix)`: registry + router under the module's plugin `api_prefix`:
  `GET {prefix}connections`, `POST {prefix}connections/{id}`, `POST {prefix}connections/{id}/{action}`
  (`test` is an action every card has), `DELETE {prefix}connections/{id}`; plus `POST /api/connections/reload-keys`
  (internal: re-read `<MODULE>_KEY_*` from the module's own `.env`, then `on_keys()` of each connector).
- `AddressConnector`: the generic «address + optional key/token + Test» service (ComfyUI, Home Assistant). The address
  is a Themis setting of the module (`<module>.<id>.address`, `editor="connection"`); the key is
  `<MODULE>_KEY_<ID>` in `Hestia-<Name>/app/.env`, written through Hephaestus.
- Who declares a connection = who talks to the service (Marko 2026-11-19): an account used by several modules
  (Google, Outlook, Garmin) is Hecate's; a service of one module stays in that module (ComfyUI → Apollo,
  Home Assistant → Lares).

### 3.2 Catalog
- New plugin contribution type `connection` (`plugin_client.connection(...)`, filled automatically from the registry):
  `{id, label, icon, what, group, keywords, in_setup, order}`. Hub catalog type `connection`; WebUI catalog types too.
- The live state always comes from the module (`{prefix}connections`), through the WebUI plugin proxy (same
  `api_prefix` guard as every plugin call).

### 3.3 WebUI
- `<hxk-connections>` in `@hestia/webui-sdk` (moved from Hecate's bundle): takes several sources
  `[{host, path}]`, merges them into one list grouped by `group` (Accounts · Devices · Home services), search past 6.
  Each card: state, step (form / wait), actions, and «Test» with its answer (facts list, e.g. GPU and models).
- Core page `/connections` «Connections» (sidebar, System) replaces Hecate's «Devices» page; the guided setup
  «Your services» step mounts the same element with `place=setup`. `?open=<module>.<id>` opens a card.
- Ctrl+K lists every connection (label + keywords) → opens its card. A setting with `editor="connection"` shows
  «Edit in Connections» instead of a free text box.

### 3.4 Secrets (choice B)
- Hephaestus `POST /api/setup/connection-secret {module, name, value}` → `<MODULE>_KEY_<NAME>` in
  `Hestia-<Name>/app/.env` (modules in `CONNECTION_MODULES`: apollo, lares, hecate, hermes), never logged nor returned,
  then the module re-reads it live (`/api/connections/reload-keys`), no restart. Clearing = empty value.
- Tokens a login produces (Google, Outlook, Garmin) stay in the module's data folder, as today: they are data, not
  something the owner types.

### 3.5 Services
- **ComfyUI (Apollo)**, group `home_service`: address + optional key; Test = `/system_stats` (version, GPU, free VRAM)
  + checkpoints found (`/models/checkpoints`). Env `APOLLO_COMFYUI_URL/KEY` removed.
- **Home Assistant (Lares)**, `home_service`: address + token (`LARES_KEY_HOME_ASSISTANT`); Test = `/api/` + how many
  entities; a change reconnects the push stream. Env `LARES_HA_URL/TOKEN` removed.
- **Google (Hecate)**, `account`: the typed client goes into Hecate's `.env` (`HECATE_KEY_GOOGLE_CLIENT_ID/SECRET`),
  `google_client.json` and env `GOOGLE_CLIENT_ID/SECRET` dropped. Action «Gmail instant notices»: topic +
  subscription (Themis `hecate.gmail.push_topic/push_subscription`) and the service-account JSON
  (`HECATE_KEY_GMAIL_PUBSUB_ACCOUNT`, one line). Env `HECATE_GMAIL_PUBSUB_*` removed.
- **Outlook (Hecate)**, `account`, new card: client ID + tenant (default `common`) + optional secret
  (`HECATE_KEY_OUTLOOK_*`) → Microsoft device-code login (wait step with code and link) → refresh token in
  `data/outlook_token.json` (survives restarts). Env `OUTLOOK_*` removed.
- **Garmin, phone (Hecate)**: same cards, groups `device`.
- **Web Push (Hermes)**: no card (nothing to link); at first start Hermes generates its VAPID pair and saves it through
  the same secret writer (`HERMES_KEY_VAPID_PUBLIC/PRIVATE`). Env `HERMES_VAPID_*` removed.
- Not in scope: brain models, embedding, voice (their own chain editor), Telegram bot token and tunnel (setup steps),
  infrastructure (Hub, DB, satellite pairing).

### 3.6 Assistant and Telegram
- Hecate tool `connections_status` (group system): every connection of every module with its state, through the
  Hub catalog + Hub route to each module; Telegram shows it with a button to the WebUI page. Linking stays in the
  WebUI (forms with passwords and codes), Google/Microsoft logins keep their existing Telegram tools.

## 4. New feature checklist (`docs/MARKO-RULES.md`)
1. Real job for the owner: link ComfyUI, Home Assistant, Google, Outlook, Garmin, phone from one page, test them.
2. Owner module (R1): each module its own connectors; the WebUI only draws them; Hephaestus only writes secrets.
3. Configuration: addresses and names = Themis settings; secrets in the module `.env` written by Hestia; no switch.
4. Push or poll: the card polls only while a page opened elsewhere is pending (as today).
5. Who confirms: the owner fills the card; the assistant only reads states (and may propose an address via Themis).
6. WebUI (icons, no emoji) and Telegram (tool + display): page «Connections», Ctrl+K; Telegram `connections_status`.
7. Stop, correct, undo: «Unlink», change address/key any time, «Cancel» on a pending login.
8. Docs that change: hestia-shared, hestia-hecate, hestia-apollo, hestia-lares, hestia-hermes, hestia-hephaestus,
   hestia-hub, hestia-webui, swagger, `.env.example`, compose, docs/ARCHITECTURE.md, docs/SETUP.md, readme where it
   mentions these variables.
9. Texts: English in `tr`, Italian in `locales/it/messages.json`; labels declared at registration plain English.
