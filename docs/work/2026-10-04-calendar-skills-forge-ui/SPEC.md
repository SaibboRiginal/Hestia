## A. Calendar (WebUI + Chronos)

### A1. Navigation bugs
- **Mini calendar**: clicking a day must move the main view to that day (day view → that day; week →
  its week; month → its month) and highlight it. Reported: nothing happens. Root cause to be confirmed by
  reproduction (Playwright, mocked API); fix + keep mini month in sync with the anchor.
- **Header arrows** step by the current view (day ±1 day, week ±7, month ±1 month, list ±30 days).
  Labels/tooltips say exactly what they do ("Giorno precedente", "Settimana successiva"…). The mini
  calendar's own arrows only page the mini month (separate, smaller, inside the mini header).
- Clicking a day header (week view) or a day number (month view) opens that day.
- Acceptance: from week view, clicking 3 different days in the mini calendar moves the grid each time;
  arrows in day view move one day.

### A2. Windows (e.g. Athena "lavora quando sei inattivo")
- Problem: rendered as full-width translucent bands behind events: unclear meaning, hard to click.
- New rendering: a **window lane** — a narrow striped column at the left edge of each day column
  (one sub-lane per overlapping window), label on hover/at the top, fully clickable; events keep the full
  width. Month view: thin bar with time range ("01:00–07:00 Athena · finestra").
- Details popover explains in plain words: "Finestra di lavoro: Athena può lavorare solo in questo
  intervallo (quando sei inattivo). Fuori dalla finestra non parte." + open/closed now, next opening.
- Setting: windows shown as **corsia** (default) · **banda** (current) · **nascoste**.

### A3. Frequent recurrences — full vs simplified
- A rule is **frequent** when it has ≥ `F` occurrences per day (default 3) — e.g. hourly Scout cycle.
- Setting "Ricorrenze frequenti": **compatte** (default) · **complete** · **nascoste**.
  - complete = every occurrence (current behaviour);
  - compatte = one summary chip per rule per day in a top "riepilogo" row of the time grid / one chip in
    month cells ("Scout · ciclo ricerca ×24 · ogni ora"), click → popover with the occurrence list (times,
    status, run result) and the rule actions;
  - nascoste = only in list view / via the module filter.
- Run status per occurrence when known (ok / failed / skipped) shown as a small dot; failures are never
  compacted away (a failed run is always visible as its own chip).

### A4. 24-hour time only
- All labels `HH:mm` (`hourCycle: 'h23'`), independent of browser/OS locale.
- Replace native `<input type="datetime-local">` (follows OS locale → AM/PM on en-US Windows) with kit
  components `<hx-date>` + `<hx-time>` (24h, keyboard friendly, 15-min suggestions). Added to the UI kit
  and `DESIGN-SYSTEM.md`.

### A5. Horizon & visibility policy ("how far ahead do I see?")
Today: whatever the view's range is (day 1, week 7, month 42, list 31 days) — nothing is filtered by
distance. New **policy** (setting "Vista focalizzata", default on; off = show everything in range):

| Class | Shown in the future | Past |
|---|---|---|
| **Manual** items (`created_by=user`) | always (it's your calendar) | always |
| **Frequent** module rules (A3) | next `Hf` days (default 7) | only failed runs, last `Dp` days, deduplicated per rule ("fallito ×3") |
| **Rare** module rules (few occurrences) | next `N` occurrences (default 3) **or** next `Hr` days (default 7), whichever ends first | same as frequent |
| One-off module items (task/event) | always | only if failed/errored, last `Dp` days |
| **Focused day** (day view, or the day picked in the mini calendar) | everything on that day, no limits | everything on that day |

- Defaults: `F=3`, `Hf=7`, `N=3`, `Hr=7`, `Dp=7` — all editable in the calendar settings.
- Hidden-by-policy items show a discreet "+12 nascoste dalla vista focalizzata" hint with one-click reveal.
- Needs per-occurrence run results → Chronos keeps a capped run log (A8).

### A6. Calendar settings
"Vista" popover in the calendar header (and mirrored in Impostazioni): windows mode, frequent mode,
focused view + thresholds, past policy, scroll-to hour / working hours highlight, week numbers,
show weekends. Stored per browser (localStorage). Time format fixed 24h, week starts Monday.

### A7. Creation: generic editor + module wizard
- Keep the generic editor (title, type, when, recurrence, action).
- **Templates declared by modules** (`AgendaTemplate`, in `hestia_common.agenda_client`): `id, owner,
  label, icon, description, type, fields` (JSON-schema like `arguments_schema`), `defaults` (duration,
  recurrence, window), `action` (Hub route/command the job calls), `max_per_user?`.
  Modules register them to Chronos at startup (idempotent, like rules): `POST /api/agenda/templates`;
  `GET /api/agenda/templates` lists them. Examples: Scout "Ricerca extra adesso / ogni giorno",
  Athena "Finestra di lavoro", Metis "Finestra di training", Hephaestus "Sviluppo programmato",
  Chronos "Promemoria", Hermes "Riepilogo notifiche".
- "Nuovo" becomes a split button: **Evento libero** · **Da un modulo…** → wizard: 1) pick module/template
  (cards) 2) fields (form generated from schema, same renderer as the Commands page) 3) when/recurrence
  (existing RRULE builder, prefilled) 4) review → create. Telegram can reuse the same templates later.

### A8. Chronos support
- Range query already exists; add `policy` params only if filtering server-side is cheaper (decided in
  implementation; default client-side).
- Per-occurrence **run log**: `meta.runs` capped (last 50) `{occurrence, ok, detail, at, by, duration_ms}`;
  occurrences expose `run: {ok, detail, at}` when present. `last_result` stays.
- Templates registry endpoints (A7). Swagger + `hestia-chronos.md` updated.

### A9. Extra ideas (mine)
- "Now" line + auto-scroll to current hour (exists? verify) and working-hours shading.
- Occurrence chip → "Log" link (Argus/Hub logs filtered by service + time ± few minutes).
- Natural-language quick add ("domani alle 15 dentista") → Oracle parses → prefilled editor.
- ICS export/feed of the AI agenda (read-only) for phones.

## B. Dynamic rules → reusable **Skills** (prompt-defined plugins)

### B1. Concept
A **Skill** is reusable logic created from a prompt, versioned, usable by any module:
- `prompt` skill — LLM template + input schema + output schema; runs through Oracle (`/api/llm/generate`),
  no code. Cheap, instant to create.
- `code` skill — Python generated by the **code model** through Forge (Claude Code or local/cloud
  engine) with a fixed interface `run(ctx, **params) -> dict` (+ optional `plan(window) -> occurrences`
  for scheduling). Tests generated, user approval required (same gate as Forge), executed sandboxed.
- Stored in Archive (only DB owner): `skills(id, name, kind, version, source_prompt, schema_in,
  schema_out, code_ref, status, created_by, changelog)`; code lives under `data/skills/<id>/v<n>/`.
- Exposed everywhere: as **MCP tools** (Oracle agent can call them), as **agenda actions** (job runs a
  skill), as **dynamic schedules** (rule whose occurrences come from `plan()`, e.g. "il giorno prima di
  ogni partita della Juve"), as **notification conditions** (Hermes), as Scout filters.
- Owner of the lifecycle: **Hephaestus** (generation, versions, approval, sandbox runner) — keeps Core
  generic; Oracle only provides LLM calls. Shared client: `hestia_common.skills` (`list/get/run/plan`).

### B2. Non-blocking generation as linked agenda items
- Creating a dynamic rule → rule item `status=generating` + a linked **generation task** item (owner
  `hephaestus`, `meta.links.parent = rule key`; rule gets `meta.links.children`). Both visible in the
  calendar ("Generazione skill… 40%").
- Success → skill version created, rule `confirmed`, bound to `skill_id@version`, notice to the user.
- Cancel the generation → rule `error` ("generazione annullata"); cancel the rule → generation
  cancelled. Failure → rule `error` with detail + retry action.
- Generic mechanism: agenda **links** with a cascade policy (`cancel_children`, `error_parent`) usable by
  any module (Forge tasks, Metis training → evaluation, etc.).

### B3. Versioning & safety
- Every edit of the source prompt → new version (v1, v2…) with changelog; rules pin a version or follow
  `latest`; rollback = pin an older version.
- Cloud/Claude engines never spend tokens without the user's OK (existing rule); local engine = auto.
- Sandbox: subprocess with timeout, no secrets in env, network allowlist via Hub only.

### B4. Open questions (to confirm with the user before implementing B)
- Name in the UI: "Skill" or "Plugin"? (proposed: **Skill**)
- Should prompt-skills also need approval? (proposed: no; code-skills: yes)

## C. WebUI "Sviluppo" (Forge + repository) page

### C1. Data Hephaestus must expose (new endpoints, swagger updated)
- Task transcript: Claude Code run with `--output-format stream-json` (Oracle `claude_code_runner`) →
  saved as `data/forge/tasks/<id>/transcript.jsonl` (messages, thinking, tool calls/results, cost,
  turns); local/cloud engines log their chat turns the same way. `GET /forge/tasks/{id}/transcript`.
- Existing: tasks list/detail, `/diff`, approve/reject/rollback. Add: `/tests` (pytest output),
  `/files` (changed files + stats), `/workdoc` (SPEC/PROGRESS/CHANGELOG markdown), `/events` (state
  timeline), `/logs` (engine + deploy logs).
- Repo (read-only, via git in the Hephaestus container): `/repo/branches`, `/repo/log?ref&path&limit`,
  `/repo/commits/{sha}` (meta + diff), `/repo/tree?ref&path`, `/repo/file?ref&path`,
  `/repo/compare?base&head`, `/repo/tags`.

### C2. Page (new menu item "Sviluppo")
- **Tasks**: list with status/engine/date/workdoc, filters, "Nuovo sviluppo" (request + services +
  engine + workdoc continuation).
- **Task detail** tabs: Panoramica (timeline, deploy plan, cost/turns, actions approve/reject/retry/
  rollback) · Conversazione (full transcript, thinking collapsible, tool calls with input/output) ·
  Modifiche (file tree + diff viewer unified/split, per-file) · Test (output, pass/fail) · Dossier
  (SPEC/PROGRESS/CHANGELOG rendered) · Log.
- **Repository**: branches (forge worktrees highlighted, ahead/behind main), commit log with graph,
  commit detail (diff), file browser at any ref, compare, tags; root CHANGELOG and `docs/work` dossiers
  browser.
- Live updates while a task runs (polling first, SignalR push later).
- Calendar: Forge items' details get "Apri in Sviluppo" + "Log" links.
